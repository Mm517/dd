# Kitchenly — متجر أدوات المطبخ

HTML + CSS + JavaScript فقط (بدون Tailwind). قاعدة البيانات والحسابات على Supabase (المشروع `krustyburger`، جداول `kt_`).

## المسارات
| الصفحة | الرابط |
|---|---|
| الرئيسية (بانر إعلاني + أقسام + عروض) | `/` |
| كل قسم | `/category/<slug>` مثل `/category/sponges` |
| العروض | `/offers/` |
| المنتجات والبحث | `/shop.html` و `/shop.html?q=...` |
| منتج | `/product-<slug>.html` |
| سلة، دفع، تتبع، دخول، لوحة تحكم | `cart.html` `checkout.html` `track.html` `auth.html` `admin.html` |
| البروفايل | `/profile` ، `/profile/my-orders` ، `/profile/my-reviews` |
| مساعدة، خصوصية، سياسات، انضم إلينا، عروضك | `/help` ، `/privacy` ، `/policy` ، `/join-us` ، `/yours-offer` |

الروابط كلها تبدأ بـ `/` فلازم الموقع يتفتح من جذر الدومين (Vercel/Netlify)، وليس بفتح الملف مباشرة. قواعد إعادة التوجيه موجودة في `vercel.json` و `_redirects`.

## البانر الإعلاني
من `js/config.js` → `banner`: الصورة والصفحة اللي يفتحها (الافتراضي `/offers/`).

## الهاشتاج
كل صفحة تعرض هاشتاج عربي يشرحها (في شريط تحت الهيدر). تعديلها من `TAGS` في `js/app.js`. صفحات الأقسام والمنتجات تأخذ اسم القسم تلقائيًا.

## البحث الذكي (Gemini)
- بحث عربي مرن في المتصفح: يتجاهل التشكيل والهمزات والتاء المربوطة، يفهم مرادفات (إسفنجة/ليفة، ممسحة/موب...) ويتحمل خطأ حرف.
- لو مفيش نتيجة مطابقة، أو عند البحث بالصورة (أيقونة الكاميرا) → الدالة `ai-search` على Supabase تستدعي Gemini وترجع اقتراحات من منتجات المتجر فقط.
- **لتفعيله:** أضف سر `GEMINI_API_KEY` (Supabase → Edge Functions → Secrets). الموديل الافتراضي `gemini-2.5-flash` ويمكن تغييره بسر `GEMINI_MODEL`. بدون المفتاح يشتغل البحث المحلي فقط.

## تسجيل الدخول بكود الإيميل
الإنشاء: بريد + كلمة مرور ← يصل كود على الإيميل ← يكتبه العميل فيتفعل الحساب. وفيه خيار "الدخول بكود يصلك على الإيميل".
**مهم:** افتح Supabase → Authentication → Email Templates، وفي قوالب *Confirm signup* و *Magic Link* ضع الكود بدل الرابط:

    <h2>كود التأكيد</h2>
    <p>الكود الخاص بك: <b>{{ .Token }}</b></p>

ولإرسال بريد لعدد كبير من العملاء اربط SMTP خاص (الإرسال الافتراضي محدود جدًا).

## الدفع (أونلاين / إنستا باي)
الخياران ظاهران في `checkout.html` ويُسجَّلان في الطلب (`online` / `instapay`). الربط يتم في `js/config.js` → `payments`:
- `instapay.handle` أو `instapay.phone`: يظهر للعميل بعد الطلب مع المبلغ.
- `online.checkoutUrl`: رابط بوابة الدفع؛ يظهر زر "ادفع الآن" ويُمرَّر له `order` و `amount`.
تأكيد الدفع الفعلي (Webhook) يُضاف لاحقًا عند اختيار البوابة.

## أدمن
سجّل حسابًا ثم نفّذ مرة واحدة في SQL editor:

    insert into public.kt_admins(email) values ('your-email@example.com');

العروض = أي منتج له "سعر قبل الخصم" أكبر من السعر؛ يظهر تلقائيًا في `/offers/`.

## التقييمات الحقيقية
جدول `kt_product_reviews` (تقييم واحد لكل حساب لكل منتج). الإضافة والتعديل عبر الدالة `kt_save_review` ولا تقبل إلا من حساب عنده طلب بحالة `delivered` فيه المنتج. متوسط التقييم وعدد التقييمات في `kt_products` يتحدثان تلقائيًا بـ trigger. لازم تغيّر حالة الطلب إلى `delivered` من لوحة التحكم عشان العميل يقدر يقيّم.

## التتبع التلقائي
من `/profile/my-orders` زر "تتبّع الطلب" يفتح `/track.html?no=...` ويعرض الطلب بدون كتابة. الزائر بدون حساب: آخر طلب من نفس الجهاز يظهر تلقائيًا.

## الاشتراك في العروض
آخر الصفحة الرئيسية، يحفظ في `kt_subscribers`. طلبات `/join-us` تتحفظ في `kt_messages` بعلامة [طلب انضمام].

## صور المنتج المتعددة
عمود `images` (jsonb) في `kt_products`. الكارت يبدّل الصور عند مرور المؤشر، وصفحة المنتج فيها مصغّرات (المرور أو الضغط). الصور اللي ما بتتحمّلش بتتشال تلقائيًا. من لوحة التحكم: خانة "صور إضافية" (رابط في كل سطر).

## الأيقونات
صور 3D في `assets/img/icons/` وتتحدد من `ICONIMG` في `js/app.js` (الأقسام، العروض، حالات الطلب، انضم إلينا).
